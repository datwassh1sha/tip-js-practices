## Организация кода

### Описание модулей проекта

- **`task-service.js`** — модуль бизнес-логики. Содержит операции над задачами: получение статистики, добавление, удаление и изменение статуса задач. Здесь хранится логика работы с полным списком задач.
- **`task-selectors.js`** — модуль отбора задач. Содержит функции для фильтрации полного списка по выбранным условиям. Фильтр определяет, какие задачи должны отображаться пользователю.
- **`task-view.js`** — модуль отображения. Создаёт DOM-элементы карточек задач, отрисовывает список, обновляет сводную информацию и сообщение о пустом списке. Не изменяет состояние приложения и не назначает обработчики событий.
- **`main.js`** — главный модуль приложения. Связывает остальные модули, обрабатывает пользовательские события, вызывает операции над задачами, применяет фильтры и обновляет интерфейс.

### Организация работы приложения

Полный список задач хранится в состоянии приложения и обрабатывается модулем `task-service.js`. Выбранные условия фильтрации хранятся отдельно в `main.js`. Пользовательские события обрабатываются в `main.js`, после чего при необходимости изменяется состояние задач и перерисовывается интерфейс. Сводная информация вычисляется функцией `getTaskStats()` из `task-service.js`, а отображается с помощью `task-view.js`.

## Отладка и клавиатура

### Проверка обработки событий

Точка останова устанавливается в функции `handleTaskListClick(event)` на строке, где определяется действие кнопки:

```js
const action = button.dataset.action;
```

Для проверки необходимо нажать кнопку изменения статуса или удаления задачи и изучить значения переменных в отладчике.

| Проверяемое значение | Ожидаемое значение или описание |
|---|---|
| `event.target` | Элемент, по которому непосредственно нажали. При нажатии на текст кнопки это может быть текстовый элемент внутри кнопки. |
| `event.currentTarget` | Элемент, на котором зарегистрирован обработчик события, — список задач. |
| `dataset.taskId` | Строковый идентификатор задачи из атрибута `data-task-id` карточки, например `"7"`. |
| Числовой `id` | Результат преобразования идентификатора с помощью `Number()`, например `7`. |
| `action` | `"toggle"` для изменения статуса или `"delete"` для удаления. |
| Результат сервиса | При корректном идентификаторе существующей задачи операция завершается успешно (`result.ok === true`). Обновлённый список находится в `result.tasks`. |

### Проверка клавиатурного управления

- **Tab:** последовательный переход фокуса между доступными кнопками и элементами управления.
- **Enter:** активация кнопки, находящейся в фокусе.
- **Space:** активация кнопки, находящейся в фокусе.
- **После изменения статуса:** фокус восстанавливается на соответствующей кнопке изменения статуса, если она остаётся доступной после повторной отрисовки.
- **После удаления:** фокус переводится на подходящую оставшуюся кнопку в списке. Если подходящего элемента нет, необходимо проверить предусмотренное приложением поведение.

### Проверка некорректных идентификаторов

| Значение `data-task-id` | Ожидаемый результат |
|---|---|
| `777` | Если задача с таким ID отсутствует, операция не выполняется, выводится сообщение «Задача не найдена.». |
| `4abc` | Значение преобразуется в `NaN`, проверка `Number.isSafeInteger(id)` не проходит. Операция не выполняется, выводится сообщение «Некорректный идентификатор задачи.». |

В обоих случаях список задач и его сводка должны остаться без изменений.

## Вывод

В ходе выполнения практической работы был разработан менеджер задач с возможностью изменения статуса, удаления задач, фильтрации списка и отображения сводной статистики. Для индивидуального варианта № 7 использован набор из шести задач, связанных с подготовкой и публикацией программного релиза.

В процессе отладки были исправлены ошибки обработки событий, обновления сводки и отображения прогресса, а также уточнены сообщения для пустого списка и отсутствия задач по выбранному фильтру. Дополнительно проверялась обработка некорректных идентификаторов и работа элементов управления с клавиатуры.

Установлено различие между изменением данных и изменением DOM: изменение DOM влияет только на отображение страницы, тогда как операции над массивом задач изменяют состояние приложения. После успешной операции обновлённый массив сохраняется в `currentTasks`, а интерфейс повторно отображается на его основе. Благодаря этому изменения сохраняются при переключении фильтров и повторной отрисовке списка.
