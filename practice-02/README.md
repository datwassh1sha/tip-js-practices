## 4. Модель данных и функции

Что должна сделать `createTask`
- Проверить `id`
- Проверить `title`:
- - это строка;
- - сделать `trim()`;
- - длина от 1 до 100.
- Проверить `priority`:
- - `"low"`, `"medium"` или `"high"`;
- - `undefined` автоматически станет `"medium"` благодаря параметру по умолчанию;
- - `null `автоматически не станет `"medium"` и должен быть ошибкой.

- Создать новый объект:
- - `completed: false`;
- - `title` уже очищенный через `trim()`.

- Вернуть `{ ok: true, task: ... }`.
- При ошибке вернуть `{ ok: false, error: "..." }`.

**Почему id не равен индексу:** `id` - уникальный идентификатор задачи. Он описывает саму задачу и не зависит от ёё положения в массиве. Индекс показывает только текущее положение элемента в списке и может меняться при взаимодействии с массивом задач.
**Почему getTaskStats возвращает число, а не строку с процентом:** Число удобно использовать для дальнейших вычислений и сортировки. Строка с символом `%` предназначена только для отображения пользоватедю и ограничивает использование результата при перечисленных выше операциях.
**Какие объекты копируются при изменении задачи:** При изменении задачи копируется сам объект задачи, чтобы не изменять исходный объект напрямую. Если задача содержит только примитивные поля `(id, title, completed, ...)`, достаточно копии через `spread({...task})`.
